2026年9月の技術メモ。

## 短縮URLサービス作りながらAWS学んでみる

AI全盛の時代に何いってんのかという感じだけどやらないよりはマシなのでやることにする。

### 1. DynamoDBでテーブル作成

短縮キーと実際のURLの対応付けのためにDynamoDBを使う。オンデマンドとプロビジョニングの２つのキャパシティがあるらしい。オンデマンドはスロットリングなどで頭打ちしない代わりに単価高、プロビジョニングは単価安い代わりに予約分以上使うとスロットリング。同量使うと5-7倍くらい価格違うとか(ChatGPT調べ) 

`url-shorter`という名前でテーブルを作成し、パーティションキーとして`shortKey`を`S`で作成。

`aws dynamodb`のサブコマンドとして`list-tables`とか`describe-table`とか`scan`とかがある模様。

### 2. Lambdaで動かすスクリプト書く

TypeScriptで`@aws-sdk/client-dynamodb`と`@aws-sdk/lib-dynamodb`使って6文字のランダムな文字列生成したり、`longUrl`をリクエストから受け取りつつ生成したランダムな文字列をDynamoDBのテーブルに放り込むスクリプトを書く。

### 3. buildしてLambdaにアップロード

zipファイルをLambdaにアップロードすることができるらしい。古代的手法。ついでにコンソール上でVSCodeも起動してるし、テストも実行できる。便利っぽい。

テストすると事前に用意してあったIAMロールのインラインポリシー名間違いとかDynamoDBのテーブル名間違いとか色々あって失敗した。最終的にうまく動けばよし。

`aws iam get-role`とか`aws iam get-role-policy`とか5分経ったら忘れてるコマンドたちを知った。

### 4. API Gatewayを追加してcurlできるようにする

API Gatewayの`HTTP API`を作成していく。`WebSocket API`とか`REST API`とか選べる。

作成時にLambda統合かHTTP統合を指定でき、今回は2で作ったLambdaを指定する。

ルートの追加でHTTPメソッド(今回はPOST)とLambdaを起動するPATH(今回は/shorten)を指定する。

ステージは`$default`のまま、そうするとAPI Gateway用のURLが払い出されるので、curlで`longUrl`をPOSTすると短縮キーを払い出してくれる。ちゃんとDynamoDBにもinsertされていた。


ここまでがDynamoDB + Lambda + API Gatewayによる短縮URL生成。生成された短縮URLで短縮前のURLにアクセスできるように、GETとリダイレクト処理を追加していく。


### 5. 短縮キーを含むGETリクエストを受けてDynamoDBから元のURLをひっぱってくるスクリプトを書いてLambdaを作成する

スクリプトの返り値はこんな感じにしてリダイレクトされるようにする。

```
return {
  statusCode: 302,
  headers: {
    Location: result.Item.longUrl,
  },
  body: "",
}
```

### 6. API Gatewayに5で作成したLambdaをキックするようにルートを作成する

スクリプトの中で`event.pathParameters?.key`みたいに書いているとして、`GET /{key}`というルートをAPI Gatewayに作成すれば指定したkey(ここでは短縮キー)をスクリプトの中で取得でき、それを元にDynamoDBに問い合わせることができるようになる。

POSTの時と同様、Lambda統合で5で作成したLambdaを指定すればヨシ。

ブラウザで短縮キー付きでAPI GatewayのURLにアクセスすると登録済みであればリダイレクトされる。

ちょっとだけハマったのは`curl -I`で試すと`404`が返ってきた。`GET /{key}`のルートなので、`curl -I`だとHEADリクエストに置き換わって`404`になる。

### 7. API GatewayのURLバレようがないから心配しすぎだけどレートとバーストは設定しておく

今回の例だと`$default`ステージしかないので、`スロットリング`からデフォルトのルートスロットリングとしてレートとバーストの数値を入れておく。

ここまでで一旦動く短縮URLサービスになった。次からちょっとずつ良くしているフェーズ。

## 短縮URLサービスにちょっとプラスアルファ

### 1. キー衝突対策

大文字小文字数字の6文字の組み合わせが衝突する確率は一旦無視して、キーが衝突した時は再生成しましょうねという処理を入れる。

ライブラリ側で条件式が用意されており、`ConditionExpression: "attribute_not_exists(shortKey)"`と書くと属性がすでに存在する場合は`ConditionalCheckFailedException`という例外を投げてくれる。

### 2. 短縮URLアクセスのアトミックカウンタ実装

ぱっと思いつくのはアクセスされるたびにDynamoDBからGETして、インクリメントしてPUT、だけど、同時アクセスがあった時に正常にカウントアップされないバグが容易におきる。

これもライブラリ側の`UpdateCommand`に条件式が用意されていて、`UpdateExpression`と`ExpressionAttributeBalues`の組み合わせでインクリメントを実装できる。

Lambda用ロールのインラインポリシーに`dynamodb:UpdateItem`を追加するのを忘れないこと。
